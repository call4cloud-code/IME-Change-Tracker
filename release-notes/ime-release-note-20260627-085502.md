# Intune Management Extension release note

## Summary

This release note is based on MSI and managed-method diff evidence comparing:

- Old MSI: `IntuneWindowsAgent_1.101.111.0.msi`
- New MSI: `IntuneWindowsAgent_1.103.101.0_manual_ffad3f11.msi`

Facts from the diff:

- File changes: `104`
- MSI table diff rows: `287`
- CustomAction diff rows: `2`
- Install sequence diff rows: `3`
- Managed method changes: `15448`

The strongest first-party functional signals are:

1. A `Microsoft.IC3.Trouter.dll` connection-lifecycle refactor with new state/generation handling and connection diagnostics.
2. Service-level additions around notification workload dispatch and compliance monitoring.
3. WinGet retry, timeout, and progress handling additions.
4. Script scheduling additions, including hourly compliance script cadence and notification scheduling.
5. MSI custom action changes for app configuration timestamp synchronization and catalog copy execution.

## Why it matters

### Interpretation

- The Trouter changes appear to make connection state transitions more explicit and serialized by using a state manager, a connection generation counter, and a connection handler.
- Notification handling appears to move toward a workload dispatch model when the related flight/configuration is enabled.
- Compliance monitoring appears to be newly integrated into the service lifecycle, with configurable poll interval handling.
- WinGet enforcement appears to gain explicit timeout and transient retry controls.
- Script scheduling appears to gain shorter cadence and notification-triggered scheduling paths.
- The Tamper Protection changes are visible in certificate validation/debug-related methods, but the evidence does not prove a specific policy or security behavior change.

## Evidence

- MSI diff:
  - `CustomAction` added: `SyncAppConfigTimestamps`
  - `CustomAction` removed: `RunCopyCatalogSilently`
  - `InstallExecuteSequence` added: `SyncAppConfigTimestamps`, condition `NOT UPGRADINGPRODUCTCODE`, sequence `799`
  - `InstallExecuteSequence` added: `CopyCatalog`, condition `NOT REMOVE`, sequence `5799`
  - `InstallExecuteSequence` removed: `RunCopyCatalogSilently`, condition `NOT REMOVE`, sequence `5799`

- Trouter focused DLL report:
  - `Microsoft.IC3.Trouter.dll` version changed `1.1.52.0` → `1.2.9.0`
  - Added `ClientStateManager::TryBeginConnectAsync`
  - Added `ClientStateManager::IsConnectingWithGenerationAsync`
  - Added `ConnectionHandler::ConnectAsync`
  - Added logging messages for stale connect generation, WebSocket timeout fallback to Long Poll, secondary transport network error ignored during switching, unregister guard, and proxy update guard.

- First-party method coverage:
  - `ScriptPlugIn.dll`: added hourly compliance cadence and notification scheduling methods.
  - `Win32AppPlugIn.dll`: added ESP registry watcher and WinGet flight methods.
  - `WinGetLibrary.dll`: added retry/timeout/progress handling methods.
  - `AgentCommon.dll`: added notification workload helper, session persistence, flighting, and environment resolution methods.
  - `IntuneWindowsAgent.exe`: added compliance monitor, IC3 check-in, proactive remediation, crash collection, and compliance precheck methods.
  - `TamperProtection.dll`: changed certificate validation/debug methods only.

## Uncertainty

- Many method changes are compiler-generated async state-machine or source-generation churn; raw method counts overstate product behavior.
- The Trouter WebSocket-to-Long-Poll fallback is evidenced by a new logging method/message; the full caller branch was not present in the provided excerpt.
- The Trouter edge from `TryBeginConnectAsync` to `ConnectionHandler.ConnectAsync` is consistent with the focused DLL report but should be validated at runtime.
- Notification workload dispatch and compliance monitor behavior appear flight/config controlled; deployment impact depends on ECS/config state.
- The Tamper Protection changes do not prove a specific certificate validation policy change from the available method names alone.
